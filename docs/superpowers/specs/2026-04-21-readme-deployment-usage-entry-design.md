# README 部署使用入口重构设计

日期：`2026-04-21`

## 背景

当前 `README.md` 已经覆盖了项目状态、模块可用度、共享 HTTP 联调结论和文档导航，但“别人第一次打开就能照着部署和使用”的入口还不够前置，也不够步骤化。

用户希望 README 首页能够做到：

- 新读者一眼知道先走哪条路径
- 团队共享部署能直接照抄
- 客户端接入步骤足够简单
- 做完后知道如何判断自己已经接通

## 本次目标

在不改动项目事实结论和统计区块的前提下，把 `README.md` 首页重构成“共享部署优先、本地单机补充”的上手入口。

## 设计原则

### 1. 首页优先共享部署

README 主路径默认围绕 `http + session` 展开，因为这是当前项目最有价值、也最适合团队落地的使用方式。

### 2. 少讲原理，多给步骤

README 首页优先提供：

- 服务端怎么启动
- 客户端怎么配置
- 首次如何调用 `auth_configure_session`
- 跑哪几个工具算接通成功

原理与扩展说明继续留给 Wiki 页面承接。

### 3. 成功标志写清楚

每条主路径都补充“看到什么算成功”，降低读者做完后仍不知道是否接通的困惑。

### 4. 本地 `stdio` 保留但降级

本地单机模式仍保留在 README 首页，但放在共享部署路径后面，作为补充入口，不与主路径竞争注意力。

## README 目标结构

README 首页调整为以下顺序：

1. 项目一句话说明
2. `3 分钟部署使用`
3. 共享部署步骤
4. 客户端接入步骤
5. 成功后的最小验证顺序
6. 本地单机使用
7. 当前状态与进阶文档入口

## 计划落地内容

### 新增一个首页速用区块

区块名称暂定：

- `3 分钟部署使用`

该区块直接给出：

- 服务端部署命令
- 最小环境变量
- 客户端 MCP 配置
- 首次鉴权调用示例
- 4 个最小验证工具

### 强化共享部署步骤

把共享部署重写为“服务器做什么 / 用户做什么”两段式结构：

- 服务器管理员
- 团队成员

### 精简首页冗余说明

README 首页减少过长的解释性段落，把：

- 深度架构
- 模块级验证明细
- 详细排障

继续交给 `docs/wiki/*` 页面承接。

## 验证方式

本次改动完成后使用以下命令验证：

- `npm run stats:check-docs`
- 检查 `README.md` 是否保留统计生成区块
- 人工确认首页顺序是否满足“共享部署优先”

## 非目标

本次不改：

- `docs/wiki/Team-Deployment.md` 的主体结构
- 统计脚本
- 产品能力矩阵
- 模块级 live 验证页
